# PodSum 项目首轮审查 — 2026-09-05

> 以下保留首轮发现时的状态。后续修复、迁移与验证进展见 [2026-09-06 发布记录](./watchless-release-20260906.md)。

## 结论

用户观察属实：Watchless 发布是“普通记录外壳 + 图文导读”，没有执行普通字幕上传的完整分析链。不是前端把已有的长 Summary 隐藏了。

这是全项目主要路径的首轮审查，不是逐行审计或渗透测试。检查覆盖 MCP/上传/发布、D1/R2、积分与任务、普通分析、详情阅读、鉴权和依赖。未读取私有文章正文、未启动收费任务、未自动修复全部安全问题、未发布新版本。

## 发现（按优先级）

### R1 / P1：私有附件的权限边界缺失 — 待修

- 位置：`app/api/files/[...key]/route.ts:4`、`lib/objectStorage.ts:186`。
- 图文 JSON API 检查公开性和所有权，但文件接口仅屏蔽 staging/runs，其他路径直接读 R2；PDF、article.json、关键帧同样受影响。
- 文件响应还声明一年 public immutable 缓存，隐私状态变化和历史内容更新均不能可靠生效。
- 影响：知道资源路径的未登录访问者可能绕过私有页面。代码路径已确认；未做线上越权下载，也不代表已发生泄露。
- 建议：文件键映射到所属播客后复用权限检查；未知/未发布键拒绝；私有 no-store，公开内容使用版本化键。需要配套评估已缓存资源。

### R2 / P1：处理入口允许客户端决定读取哪个对象 — 待修

- 位置：`app/api/process/route.ts:1117`、`:1197`、`lib/objectStorage.ts:194`。
- 只验证请求中的 podcast ID 归属，却使用请求中的另一个 `blobUrl` 读取内容，没有绑定到数据库的 podcast.blobUrl。
- 影响：持有自己播客的登录用户可以请求处理任意已知 R2 键，或让服务端抓取其他 URL。内部网络可达性未测试，不将其表述为已成功 SSRF。
- 建议：只从数据库取规范源，外部 URL 采用明确域名/协议及响应大小限制；普通请求不能覆盖源地址。应优先于扩大自动处理能力。

### R3 / P1：bundle 导读被当成完整分析 — 待接通分析流程

- 位置：`lib/watchless/jobs.ts:1020`、`app/api/process/enqueue/route.ts:36`。
- 发布仅把 `article.summaryZh/En` 写入 Summary；没有调用普通处理链的 Summary、数据/行动项、脑图等生成。
- `analysis_results` 行存在就被 enqueue 认为已经处理，常规补齐因此也被跳过。
- 9 篇 MCP 记录全部只有短导读，与用户看到的情况吻合。
- 建议：增加明确的分析产物状态，区分 overview 与 complete。MCP 可附带经校验的完整 analysis；未附带时，在明确计费策略下进入共享分析队列。图文发布和分析失败应独立，不能因分析重试覆盖图文或原话。
- 本轮没有把导读扩写成假分析，也未批量调用模型补历史内容。

### R4 / P1：Full Text 字段错位且截断 — 本地已修，未回填/发布

- 位置：`lib/watchless/jobs.ts` 发布映射；新增 `lib/watchless/analysisProjection.ts`。
- 普通页面约定 `translation=英文全文`、`highlights=中文全文`。旧 bundle 发布却写入 `translation=中文正文前22000字符`、`highlights=前8个场景标题`。
- 影响：English 显示中文，中文只剩标题，长文丢尾部，词汇提示无有效英文。下方独立 WatchlessReader 读的是 article.json，因此看起来反而正常。
- 修复：按既有字段约定保留全部场景中英文，生成场景级对齐数据；明确拒绝超过数据库行预算的内容，不再静默截断。没有声称场景对齐就是句子对齐。
- 测试：超过22000字符、超过8场景、逐字保留、规范化兼容、超限拒绝。
- 历史行尚未修改；必须备份并按 article.json 回填后才会修好现有页面。

### R5 / P2：无 transcript 的 bundle 把 article.json 当字幕 — 待修

- 位置：`lib/watchless/jobs.ts:1004`、`app/api/process/route.ts:1197`。
- transcript 是可选附件，缺失时 podcast.blobUrl 指向 article.json，但 original_filename 仍写成 txt。
- 影响：点击重新处理可能把整个 JSON（含元数据、重复中英文和画面说明）送入字幕分析，问答检索也可能受污染。
- 建议：保存从明确 sourceTranscript 提取的规范源文本，或要求原字幕；读取已授权 Watchless 源时使用专用适配器。该问题修复前不建议批量点击重新处理。

### R6 / P2：Sam Altman 特例优先读本地样例 — 待修

- 位置：`lib/watchless/publications.ts:30`、`app/dashboard/[id]/page.tsx:1484`。
- 匹配到该视频时，生产详情直接用打包样例并跳过远程 publication 查询。
- 影响：MCP 更新/回填后的服务器文章可能不被展示，样例状态也不等于真实发布状态。
- 建议：生产页面只用受权限保护的远程数据；样例仅用于开发预览。需补生产/开发隔离回归测试。

### R7 / P2：关键帧按文件名字典序映射，而不是按场景引用 — 待修

- 位置：`lib/watchless/jobs.ts:880`、`:978`、`:991`。
- 校验只要求图片数量足够，发布按排序后第 n 张绑定第 n 场景，不核对 scene.keyframe 指向的附件。
- 影响：非补零命名（如 scene_1、scene_10、scene_2）或额外封面图可导致画面与正文错位。代码路径明确，未断言这9篇已经错位。
- 建议：规范化相对路径后建立精确一一映射，拒绝缺失/重复引用，测试非字典序命名。

### R8 / P2：依赖存在已知安全告警 — 待评估可达性及升级

- 本地 `npm audit --omit=dev`：11 个受影响依赖条目，3 high、4 moderate、4 low；不是11个已证明可利用漏洞。
- high 涉及 jsondiffpatch、PostCSS、嵌套 undici。自动建议包含跨大版本升级，未执行 `audit fix --force`。
- 必须先判断运行路径、移除未使用旧依赖，再分组升级并重跑 Cloudflare 构建。不能用 Jest 通过替代漏洞可达性分析。

### R9 / P2：声称“原话”的验证仍主要依赖声明与语言检测 — 待加强

- 位置：`lib/watchless/jobs.ts:869`、`:950`、`lib/watchless/bilingual.ts:6`。
- 当前校验覆盖时间线、字段、语言和附件数量，但不普遍证明 article 正文与原始字幕逐条一致。已声明 verbatim + translation 的 bundle 可通过语言校验。
- 线上公开样例仍可见说话人混合及 ASR 存疑词。此处是数据质量证据，不将未听音频的文本修改成“正确原话”。
- 建议：manifest 记录 source SHA、utterance IDs、时间边界和说话人出处；对英文原话做归一化前后差异校验。翻译和编辑导语明确分开。

## UI 审查及本地优化

视觉方向通过：暖纸张、深绿操作和正文阅读保持一致，没有新增炫光、营销型 hero 或重复卡片。

本轮改善：
- 分析区增加完整图文跳转入口和用途说明；Watchless 问答默认收起，首次打开才加载，收起不卸载输入状态。
- Watchless 来源图改为紧凑布局，减少首屏占用；短导读不再强撑320px空白；标题改为页面 h1。
- 空摘要/全文不再在没有任务时显示“正在生成”；脑图缺失明确说明是独立产物。
- 内容视图和语言按钮暴露选中状态、焦点样式与触控高度。
- 收起的完整图文 inert，避免键盘进入不可见区域；收起滚动尊重 reduced-motion；未打开时不显示假加载状态。

移动端与桌面截图使用本地页面 + 指定公开文章 API 的只读代理做 UI 验证；拒绝 POST、屏蔽登录/私有数据，不代表历史数据已修复。无全站性能基准或所有页面逐一截图，未编造对比度评分。

## 七项审查归纳

1. 边界/错误路径：全文超限、缺附件、语言/原话不一致、无数据假加载。
2. 清晰与一致性：legacy字段名称含义和 bundle 写入不一致；来源与分析状态需显式建模。
3. 可维护性：详情页与处理路由体积大，后续拆分应按能力边界逐步做，不在本轮整体重写。
4. 安全：R1、R2 应先修；已有 MCP scope、所有权校验、内部签名及参数化SQL是正面基础。未提供 security-review skill，本轮以手工跨入口检查替代。
5. 性能：问答懒加载已改善；仍需另做首页真实基准及大文章响应预算。
6. 文档：本报告与计划明确未发布、未回填及未跑完整转换的边界。
7. 风格/测试：继续复用设计令牌与原阅读组件；补字段映射、无截断、折叠键盘与QA行为测试。

## 建议执行顺序

1. 先封堵 R1/R2 并验证私有/公开/所有者三种状态。
2. 修复规范源读取与样例覆盖，接通完整分析状态和共享队列。
3. 备份后给9篇 MCP bundle 回填 Full Text，挑1篇验证完整 Summary/脑图及费用，再决定是否批量补齐。
4. 发布 Worker + GLM Container，并做一次端到端转换；目前 GLM API 单次测试成功不等于线上转换已切换。
5. 分组更新依赖、完成全站性能基准。
